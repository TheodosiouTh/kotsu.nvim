1. INTRODUCTION                                                  *kotsu-intro*

Ask in plain language how to do something ("delete to the end of the
paragraph") and get the fastest key sequence in a centred popup. Your own
mappings (those with a description) are sent as context, so answers prefer
your bindings over generic ones.

Requires Neovim 0.10 or newer and a backend (by default the Claude Code CLI,
`claude`, on your PATH).

==============================================================================
2. USAGE                                                         *kotsu-usage*

                                                                      *:Kotsu*
:Kotsu {question}       Ask {question} directly.
:Kotsu                  Open an input prompt for the question.

<Leader>?               Open the input prompt (see |kotsu-config| `keymap`).

In the popup, `q` or <Esc> closes it. Leaving the window (e.g. to type the
suggested key sequence) hides it instead: the last answer is kept, and a
toggle brings the popup back up. Asking a new question while one is hidden
discards it and starts fresh.

                                      *<Plug>(kotsu-prompt)* *<Plug>(kotsu-toggle)*
<Plug> mappings are always available, so you can bind the prompt and the
hide/unhide toggle yourself without calling `setup()` and without loading
the plugin eagerly:
>lua
  vim.keymap.set("n", "<Leader>?", "<Plug>(kotsu-prompt)",
    { desc = "How do I…?" })
  vim.keymap.set("n", "<Leader>!", "<Plug>(kotsu-toggle)",
    { desc = "Hide/unhide kotsu" })
<
`q`/<Esc>, or asking a new question, cancel a pending request for real:
the backend process is killed (if the backend supports that) and its
answer, if it arrives late anyway, is discarded. Hiding the popup does
neither: the request keeps running and its answer is kept for when you
unhide.

Lua API:                                                           *kotsu-api*
>lua
  require("kotsu").setup(opts)   -- apply options and the keymaps
  require("kotsu").ask("...")    -- ask a question
  require("kotsu").prompt()      -- open the input prompt
  require("kotsu").toggle()      -- hide/unhide the popup
<
==============================================================================
3. CONFIGURATION                                                *kotsu-config*

Call `setup()` with any options you want to change. Defaults:
>lua
  require("kotsu").setup({
    -- Normal-mode mapping for the prompt. `false` = no mapping.
    keymap = "<Leader>?",
    -- Normal-mode mapping to hide/unhide the popup. `false` = no mapping.
    toggle_keymap = false,
    -- "claude" or a function. See |kotsu-backend|.
    backend = "claude",
    timeout_ms = 60000,
    model = "haiku",  -- forwarded to the backend, e.g. --model
    effort = "low",   -- forwarded to the backend, e.g. --effort
    context = {
      modes = { "n", "x", "o", "i" },  -- whose mappings are sent
      max_mappings = 500,
    },
    prompt = {
      extra = nil,  -- extra prompt text, e.g. "I use AstroNvim."
    },
    window = {
      border = "rounded",
      min_width = 40,
      max_width = 0.7,   -- fraction of editor columns
      max_height = 0.6,  -- fraction of editor lines
    },
  })
<
`:Kotsu` works without calling `setup()`; the defaults are used and no
keymap is created.

==============================================================================
4. BACKENDS                                                    *kotsu-backend*

Built in:

  "claude"    Runs `claude -p <prompt>` (Claude Code CLI), always with
              --safe-mode --tools "" --no-session-persistence, so it never
              loads your CLAUDE.md, hooks, skills, MCP servers or plugins,
              and never writes a session to disk. Not configurable.
              `model`/`effort` (see |kotsu-config|) are passed through as
              --model/--effort when set.

Custom backend: pass a function instead of a name.
>lua
  backend = function(prompt, opts, on_done)
    -- opts.timeout_ms, opts.model, opts.effort are the configured values
    -- (model/effort may be nil).
    -- Call on_done(true, answer) or on_done(false, error_message).
    -- on_done can be called from any context.
    -- Return a handle with :kill(signal) and :is_closing() (like
    -- vim.system's return value) to support cancelling when the popup
    -- closes early; optional.
  end
<
==============================================================================
5. HEALTH                                                       *kotsu-health*

`:checkhealth kotsu` checks the Neovim version, whether the backend is
available, and how many mappings with descriptions were found.

==============================================================================
6. LIMITATIONS                                             *kotsu-limitations*

- Answers are not yet checked against your real mappings.
- One question at a time; no follow-ups.
